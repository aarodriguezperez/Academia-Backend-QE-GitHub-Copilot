PROYECTO 1 - SEMANA 1
TALLER AUTOMOTRIZ
Conceptos utilizados

1. CLASES ABSTRACTAS
Se usan en Vehiculo, Persona y Servicio.
Estas clases sirven como base para otras clases y no se crean directamente.

Ejemplo:
Vehiculo es la clase padre de Automovil, Camioneta y Motocicleta.

2. HERENCIA / IS-A
Se usa cuando una clase es un tipo de otra.

Ejemplos:
- Automovil IS-A Vehiculo
- Camioneta IS-A Vehiculo
- Motocicleta IS-A Vehiculo
- Cliente IS-A Persona
- Mecanico IS-A Persona
- Reparacion IS-A Servicio

3. HAS-A
Se usa cuando una clase contiene objetos de otra clase.

Ejemplos:
- Cliente tiene una lista de Vehiculo.
- Orden tiene Cliente, Mecanico, Vehiculo, Servicio y Refaccion.

4. POLIMORFISMO
Se usa con el metodo costoInspeccion() de Vehiculo.

Automovil, Camioneta y Motocicleta tienen su propia version de este metodo.
Aunque las variables se declaran como Vehiculo, se ejecuta el metodo de la clase real del objeto.

5. UPCASTING
Se usa al guardar un objeto de una clase hija en una referencia de la clase padre.

Ejemplo:
Vehiculo v1 = new Automovil(...);

El objeto sigue siendo Automovil, pero se maneja con una referencia Vehiculo.

6. DOWNCASTING
Se usa para volver de una referencia de la clase padre a una clase hija especifica.

Ejemplo:
if (v2 instanceof Camioneta) {
    Camioneta camioneta = (Camioneta) v2;
}

Esto permite usar metodos propios de Camioneta, como getCapacidadCarga().

7. INTERFACES
Se creo la interfaz EstrategiaCosto.

Esta interfaz tiene el metodo:
calcularCosto(double subtotal)

La implementan:
- CostoNormal
- CostoDescuento

Tambien se usan las interfaces Comparable y Comparator.

8. STRATEGY
Se usa para cambiar la forma en que se calcula el total de una orden.

La orden puede utilizar:
- CostoNormal
- CostoDescuento

La estrategia se cambia con asignarEstrategiaCosto().

9. SINGLETON
Se usa en la clase Taller.

La clase tiene un constructor privado y el metodo getInstancia().
Esto hace que durante la ejecucion se trabaje con una sola instancia de Taller.

En Principal se comprueba comparando:
taller1 == taller2

10. COMPARABLE
Orden implementa Comparable<Orden>.

Se usa compareTo() para ordenar las ordenes por su id.

Despues se utiliza:
Collections.sort(listaOrden);

11. COMPARATOR
Se creo ComparatorPorCosto.

Sirve para ordenar las ordenes usando otro criterio, en este caso el costo total.

Se utiliza con:
Collections.sort(listaOrden, new ComparatorPorCosto());

12. GENERICS
Se usan para indicar que tipo de objetos puede guardar una lista.

Ejemplos:
- List<Vehiculo>
- List<Servicio>
- List<Refaccion>
- List<Orden>

Tambien aparecen en Comparable<Orden> y Comparator<Orden>.

13. LAMBDAS
Se usa una lambda para recorrer la lista de ordenes.

Ejemplo:
listaOrden.forEach(orden ->
        System.out.println("Orden: " + orden.getIdOrden()));

La lambda toma cada orden de la lista y ejecuta una accion.

14. FINAL
Se usa final en los identificadores.

Ejemplos:
- idVehiculo
- idPersona
- idServicio
- idRefaccion
- idOrden

Esto evita que el id cambie despues de crear el objeto.

15. STATIC
Se usa principalmente en Singleton.

Ejemplo:
private static Taller instancia;

Tambien se usa en el metodo main:
public static void main(String[] args)

16. CONSTRUCTORES
Las clases utilizan constructores para recibir los datos iniciales de los objetos.

Las clases hijas utilizan super(...) para llamar al constructor de la clase padre.

17. ENCAPSULACION
Los atributos de las clases se manejan principalmente como private.

Para acceder o modificar los datos se usan getters, setters o metodos controlados.

Ejemplo:
actualizarKilometraje()

18. GETTERS Y SETTERS
Se usan para consultar o cambiar atributos privados.

No todos los atributos tienen setter.
Por ejemplo, los id son final y solamente tienen getter.

19. EXCEPTIONS
Se usa IllegalArgumentException para evitar valores incorrectos.

Un ejemplo esta en actualizarKilometraje().
Si se intenta colocar un kilometraje menor al actual, se lanza una excepcion.

En Principal se usa try-catch para capturarla y permitir que el programa siga funcionando.

20. MODIFICADORES DE ACCESO
public:
Se usa en metodos y clases que deben poder utilizarse desde otros paquetes.

private:
Se usa principalmente en los atributos para proteger los datos.

default:
Se usa cuando no se escribe ningun modificador.
En el proyecto aparece en calcularSubtotal() de Orden.

protected:
No se agrego en el proyecto porque no habia una necesidad real de utilizarlo.

21. OVERRIDE
Se usa @Override cuando una clase cambia la implementacion de un metodo heredado o de una interfaz.

Ejemplos:
- costoInspeccion()
- calcularCosto()
- compareTo()
- compare()
- toString()


RESUMEN

El proyecto Taller Automotriz utiliza Programacion Orientada a Objetos para manejar clientes, mecanicos, vehiculos, servicios, refacciones y ordenes.

Los conceptos principales utilizados fueron:
- Clases abstractas
- Herencia
- IS-A
- HAS-A
- Polimorfismo
- Upcasting y Downcasting
- Interfaces
- Strategy
- Singleton
- Comparable y Comparator
- Generics
- Lambdas
- Final y Static
- Constructores
- Encapsulacion
- Getters y Setters
- Exceptions
- Modificadores de acceso
- Override
